# 질문형 제목 한 줄
title: 질문형 제목을 한 줄로 적어 주세요?

# "이 레슨을 마치면 ~할 수 있다" 한 줄
goal: 이 레슨을 마치면 할 수 있게 되는 것을 한 줄로 적어 주세요

# 홈에 보이는 순서 (다른 레슨과 겹치면 안 됨)
order: 99

# 준비중 = 홈에 잠긴 카드로만 보임 / 공개 = 열람 가능. 다 채우면 공개로 바꾸세요
status: 준비중

# 아래 :::patch 블록의 내용을 확인한 패치 버전. 반드시 따옴표로 감싸기 ("26.20" 이 26.2 로 바뀌는 것 방지)
verifiedPatch: "26.22"

# 검수 전 또는 확인해 준 사람(티어). 예: 홍길동(다이아) → 화면에는 "검수: 홍길동(다이아)"로 보임
# 주의: 값 안에 "검수: " 처럼 콜론+띄어쓰기를 넣으면 YAML 오류가 납니다
review: 검수 전

# 정확히 3줄
summary:
  - 요약 첫째 줄
  - 요약 둘째 줄
  - 요약 셋째 줄

# 출처 2개 이상 권장. 남의 글·영상은 그대로 옮기지 말고 요약해서 쓰고 링크를 단다
sources:
  - title: 출처 이름 (예시 - 패치 노트 26.22)
    url: https://example.com
    checkedAt: 2026-11-05

## 원칙

패치가 바뀌어도 유지되는 판단 기준을 글로 씁니다.
상황에 따라 달라지는 내용은 단정하지 말고 "대체로", "조건: ~"처럼 조건과 함께 적습니다.

:::patch
수치, 타이밍, 루트처럼 패치마다 바뀌는 내용은 이 블록 안에만 씁니다.
새 패치가 나오면 이 블록만 다시 확인하고 verifiedPatch 를 고칩니다.
:::
