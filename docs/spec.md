# 정글 교과서 — 기획서 v0.1 (MVP)

Nov 5, 2026 · @wlgns

## 개요

**정글 교과서는 정글을 처음 해보는 롤 플레이어가 겪는 세 가지 막막함(어디서 시작할지, 지금 뭘 할지, 적 정글러가 어디 있는지)을 레슨과 상황 퀴즈로 풀어주는 웹 강좌입니다.** 장기 목표는 완전 기초부터 심화까지이고, 1단계(MVP)는 레슨 3개입니다.

- **이전 방향과의 관계**: 챔피언 전체의 스킬 판정을 모으는 '판정 사전'은 범위가 커서 보류했습니다. 그 기획서의 '직접 검증', '패치 버전 표시', '시각 자료 중심' 원칙은 이어서 씁니다.
- **이 문서의 용도**: Claude Code에 넘기는 spec입니다. 무엇을, 왜 만드는지를 정하고, 어떻게(기술 스택, 폴더 구조, 데이터 저장 방식)는 Claude Code가 제안합니다.
- **작성자**: 실버 티어 정글 플레이어이고, 이 서비스의 첫 사용자입니다. 개발 경험은 거의 없습니다.
- **형태**: 웹으로 시작하고, 휴대폰 화면에서도 읽히게 만듭니다.

## 문제와 목표

**실버 구간의 정글 입문자는 '어디서 시작해 어떻게 도는지', '지금 뭘 해야 하는지', '적 정글러가 어디 있는지'를 몰라서 정글을 어려워합니다.** 이 세 가지는 작성자 본인의 경험이고, 다른 입문자도 같은지는 친구 테스트로 확인할 가설입니다. 영상 강의는 이미 많지만, 보는 것만으로는 '그 순간에 무엇을 고를지' 판단하는 연습이 되지 않는다는 점도 가설로 둡니다.

### 목표

1. 세 가지 막막함에 하나씩 대응하는 레슨 3개를 공개한다.
2. 레슨마다 상황 퀴즈로 선택을 연습하고, 선택 직후에 이유를 해설로 듣게 한다.
3. 레슨의 모든 내용에 출처와 확인한 패치 버전을 표시한다.
4. 작성자와 친구 몇 명이 레슨을 보고 실제 게임에서 써본 뒤, 덜 막막해졌는지 확인한다.

## 타깃 사용자와 사용자 스토리

**첫 사용자는 작성자 본인(실버 정글러)이고, 그다음은 정글을 피하는 친구들입니다.** 장기적으로는 정글을 처음 시도하는 모든 입문자가 대상입니다.

### 사용자 스토리

- 정글 입문자로서, 게임 시작 때 어디서 시작하고 어떤 순서로 도는지 알고 싶다. 첫 몇 분을 헤매지 않기 위해서다.
- 정글 입문자로서, 지금 할 일을 고르는 기준을 알고 싶다. 갱, 파밍, 오브젝트 사이에서 망설이다 시간을 잃지 않기 위해서다.
- 정글 입문자로서, 적 정글러의 위치를 추정하는 방법을 알고 싶다. 위치를 모를 때의 불안을 줄이기 위해서다.
- 학습자로서, 상황 퀴즈로 선택을 연습하고 이유를 바로 듣고 싶다. 읽기만 해서는 판단력이 늘지 않기 때문이다.
- 학습자로서, 내용이 어느 패치 기준이고 출처가 어디인지 알고 싶다. 믿어도 되는지 스스로 판단하기 위해서다.
- 만드는 사람으로서, 정해진 양식으로 레슨을 추가하고 싶다. 코드를 고치지 않고 내용을 늘리기 위해서다.

## MVP 범위

**MVP는 레슨 3개와 레슨마다 상황 퀴즈를 담은 웹 강좌입니다.**

### 레슨 후보 (확정 전)

1. 시작과 첫 클리어: 어디서 시작하고 어떤 순서로 도는가
2. 지금 뭘 할까: 갱, 파밍, 오브젝트 중 고르는 기준
3. 적 정글러 찾기: 위치를 추정하는 방법과 불안을 줄이는 습관

### 반드시 포함 (P0)

| 요구사항 | 인수 기준 |
| --- | --- |
| 홈의 강좌 지도 | 레슨 3개가 순서대로 보이고, 각 레슨을 열 수 있다 |
| 레슨 화면 | 읽기, 상황 퀴즈, 해설, 3줄 요약이 한 흐름으로 이어진다 |
| 상황 퀴즈 | 레슨당 3\~5문제(제안). 선택하면 즉시 정답과 이유가 보인다 |
| 출처와 패치 표시 | 모든 레슨에 출처 목록과 확인한 패치 버전이 보인다 |
| 진행도 | 완료한 레슨이 로그인 없이 이 기기에 기억된다 |
| 레슨 추가 방식 | 만드는 사람이 코드를 고치지 않고 양식 파일에 레슨을 적어 추가할 수 있다 |
| 모바일 화면 대응 | 휴대폰 화면 너비에서도 글, 퀴즈, 도식이 깨지지 않는다 |

### 있으면 좋은 것 (P1)

- 틀린 퀴즈만 모아 다시 풀기 (오답 노트)
- 게임 시작 전 1분 체크리스트 화면
- 용어 설명 (캠프, 스마이트 등)
- 지도 위에 동선을 표시한 도식

### 구조만 대비 (P2)

- 레슨 4번 이후와 심화 과정
- 챔피언별 가이드, 다른 포지션
- 로그인과 전적 연동, AI 질문, 앱 버전

### 제외

- **로그인과 회원**: 진행도는 기기에 저장해서 해결합니다.
- **AI 답변**: 검증된 레슨이 쌓이기 전에는 오답 위험이 큽니다.
- **전적 연동**: 정책과 승인 부담이 큽니다.
- **영상 강의 제작**: 도식, 이미지, 퀴즈 중심으로 갑니다.
- **네이티브 앱**: 웹으로 먼저 검증합니다.

## 레슨 구성

**레슨 한 편은 '읽기 → 상황 퀴즈 → 해설 → 요약' 순서이고, 오래 유지되는 원칙과 패치마다 바뀌는 정보를 따로 둡니다.** 정글은 패치 영향을 크게 받아서, 바뀌는 부분만 고칠 수 있어야 합니다.

| 필드 | 설명 | 필수 |
| --- | --- | --- |
| 제목 | 질문형 한 줄 | 예 |
| 이 레슨을 마치면 | 한 줄 목표 | 예 |
| 원칙 | 패치가 바뀌어도 유지되는 판단 기준 | 예 |
| 패치 의존 정보 | 수치, 타이밍, 루트 등. 별도 블록으로 분리 | 해당 시 |
| 검증 패치 | 패치 의존 정보를 확인한 패치 버전 | 패치 의존 정보가 있으면 예 |
| 시각 자료 | 도식 또는 이미지 | 권장 |
| 상황 퀴즈 | 상황, 선택지, 정답, 이유 해설 | 예 |
| 요약 | 3줄 | 예 |
| 출처 | 링크와 확인일 | 예 |
| 검수 | 확인해 준 사람과 티어, 또는 '검수 전' | 예 |

### 상황 퀴즈의 모양

한 문제는 **상황 설명 → 선택지 3\~4개 → 정답 → 왜 그런지**로 이루어집니다. 상황 설명에는 게임 시간, 내가 아는 맵 정보, 모르는 정보를 함께 적어서 '정보가 부족한 상태에서 고르는 연습'이 되게 합니다. 정답이 상황마다 달라지는 문제는 조건을 적고, 정답을 하나로 단정하지 않습니다. 내용은 작성자가 출처를 바탕으로 채우고, 이 문서에서는 형식만 정합니다.

## 콘텐츠 정확성

**작성자가 실버 티어이므로, 레슨 내용은 작성자의 경험이 아니라 확인할 수 있는 출처에 근거합니다.** 틀린 내용이 있는 교과서는 한번 신뢰를 잃으면 회복하기 어렵습니다.

- **근거의 우선순위**: ① Riot 공식 자료(패치 노트, 공식 게임 정보) ② 상위 티어 플레이어와 코치의 공개 콘텐츠 ③ 작성자가 직접 해보고 확인한 것
- **출처 표시**: 레슨마다 출처를 2개 이상(제안) 링크로 적고, 확인한 날짜를 남깁니다. 타인의 글이나 영상은 그대로 옮기지 않고 요약해서 쓰며 링크를 답니다.
- **검수**: 상위 티어 지인이 있으면 레슨을 한 번 읽어 달라고 하고 '검수: 이름(티어)'를 표시합니다. 없으면 '검수 전'으로 표시합니다.
- **단정 금지**: 상황에 따라 달라지는 내용은 '대체로', '조건: \~'처럼 조건과 함께 적습니다.
- **패치 대응**: 패치 의존 정보에는 검증 패치를 표시합니다. 새 패치에서 정글 관련 변경이 있으면 해당 블록만 다시 확인합니다(수동).
- **눈높이 (제안)**: '정글을 배우며 만든 교과서'라는 점을 숨기지 않는 톤을 권장합니다. 입문자에게는 같은 눈높이가 장점이 됩니다.

## 핵심 화면과 사용자 흐름

**화면은 홈, 레슨, 상황 퀴즈, 요약과 출처 네 가지입니다.**

1. **홈**: 레슨 3개를 순서대로 보여주는 강좌 지도, 완료 표시
2. **레슨**: 목표 한 줄, 원칙, 패치 의존 정보 블록, 시각 자료
3. **상황 퀴즈**: 문제 한 개씩, 선택하면 즉시 정답과 이유
4. **요약과 출처**: 3줄 요약, 출처 목록, 검증 패치, 검수 표시

### 사용자 흐름

1. 홈에서 레슨을 고른다.
2. 레슨을 읽는다.
3. 상황 퀴즈를 푼다 (문제마다 즉시 해설).
4. 3줄 요약을 확인하고 완료 표시를 한다.
5. 다음 레슨으로 이동한다.

### 빈 상태와 오류

- 아직 공개되지 않은 레슨은 '준비 중'으로 표시하고 열리지 않습니다.
- 진행도를 저장하지 못하면 '이 기기에 저장되지 않았습니다'를 알려 주되, 레슨은 계속 볼 수 있습니다.

## 성공 지표와 완료 기준

**MVP는 레슨 3개가 공개되고, 써본 사람이 '덜 막막해졌다'고 답하면 성공입니다.** 아래 목표 숫자는 제안값이며 본인이 조정합니다.

| 구분 | 지표 | 목표 | 측정 방법 |
| --- | --- | --- | --- |
| 완료 | 공개된 레슨 수 | 3개 | 사이트 확인 |
| 완료 | 출처 또는 검증 패치가 빠진 레슨 | 0개 | 양식 점검 |
| 선행 | 레슨을 보고 실제 게임에서 1가지 이상 써봤다고 답한 비율 | 70% 이상 | 대화나 간단한 설문 |
| 선행 | 해당 막막함이 덜해졌다고 답한 비율 (레슨별) | 50% 이상 | 대화나 간단한 설문 |
| 선행 | 퀴즈 첫 시도 정답률 | 40\~80% (너무 쉽거나 어렵지 않은지 확인) | 친구에게 풀게 하고 기록 |
| 후행 | 1주 뒤 다시 접속한 사람 비율 | 절반 이상 | 대화로 확인 |

**판단 기준**: '덜해졌다'가 50% 미만인 레슨은 내용을 고친 뒤에 다음 레슨으로 넘어갑니다.

## 단계별 로드맵

**레슨 1\~3의 성공 지표를 확인한 뒤에 다음 레슨을 만듭니다.** 하드 데드라인은 없습니다.

1. **1단계 (이 spec)**: 레슨 1\~3과 상황 퀴즈, 출처와 패치 표시, 진행도 저장
2. **2단계**: 레슨 4\~6 (중립 오브젝트와 시야, 이기는 상황과 지는 상황의 판단, 갱 이후의 행동), 오답 노트, 게임 전 1분 체크리스트
3. **3단계, 심화**: 챔피언 폭 넓히기, 메타 변화에 따른 루트, 다른 포지션 검토

다음 단계로 가는 조건은 성공 지표 충족입니다. 3단계 전에는 검수자를 확보하거나 검수 방식을 정합니다.

## 리스크와 열린 질문

**가장 큰 리스크는 작성자가 실버 티어라서 생기는 내용의 정확성과, 패치로 인한 최신성입니다.**

### 리스크

- **정확성**: 대응은 출처 우선순위, 검수 표시, 단정 금지입니다.
- **최신성**: 대응은 원칙과 패치 의존 정보의 분리, 검증 패치 표시입니다.
- **제작 시간**: 레슨 3개를 근거와 함께 쓰는 일이 개발보다 오래 걸릴 수 있습니다. 대응은 레슨 단위로 완성해서 공개하는 것입니다.
- **차별점이 약할 수 있음**: 정글 영상 강의는 이미 많다는 가정입니다. 이 서비스의 차별점은 '상황 퀴즈로 선택을 연습하고 즉시 이유를 듣는 것'과 '입문자의 막막함에서 출발한 구성'이며, 친구 테스트로 확인합니다.
- **개발 경험 부족**: 작게 나눠 진행하고 단계마다 직접 실행해 확인합니다.

### 열린 질문

| 질문 | 담당 | 차단 여부 |
| --- | --- | --- |
| 레슨 3개의 주제와 순서 확정 | 본인 | 레슨 작성 전 |
| 상위 티어 검수자가 있는가 | 본인 | 아니오 |
| 출처로 쓸 자료 목록 (공식 자료와 공개 콘텐츠) | 본인, 필요하면 Claude가 조사 | 레슨 작성 전 |
| 도식과 이미지: 직접 그린 도식으로 갈지, 게임 화면을 쓸지, Riot 정책은 어떤지 | 본인 확인 | 공개 전 |
| 진행도를 기기에만 저장해도 충분한가 | Claude Code 제안 후 본인 결정 | 구현 전 |
| 사이트 이름과 공개 범위 | 본인 | 아니오 |

## Claude Code 작업 지침

**구현 방식은 Claude Code가 이 spec을 읽고 제안하고, 코드를 쓰기 전에 계획부터 승인받습니다.**

- 작성자는 개발 경험이 거의 없습니다. 단순하고 관리하기 쉬운 구성을 우선하고, 선택한 이유를 쉬운 말로 설명해 주세요.
